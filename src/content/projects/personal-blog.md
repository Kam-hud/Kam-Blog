## 项目背景

就是你正在看的这个站点。它被推翻重做过一次：第一版是手写 HTML/CSS/JS 的静态站，在第三个页面之后就撑不住了，于是换成了 Vue 3 + Vite。

定位是「作品集 + 随笔」的混合体：作品区放做过的东西，每个都配一个能直接点开的 Demo；文章区主要写技术笔记，偶尔夹一点随笔。

## 做了什么

- **Markdown 驱动内容**：文章和项目都是 `src/content/` 下的 `.md` 文件。新建一个文件，列表页、首页的最新列表、按年份分组会一起自动更新。
- **暗色 / 亮色切换**：基于 CSS 变量的一套设计令牌，切换只需要换一个 `data-theme` 属性；`<head>` 里的内联脚本负责消除首帧白闪。
- **代码高亮**：highlight.js 公共语言包，构建时完成渲染，不请求 CDN。
- **文章目录**：从 Markdown 的标题 token 流里提取 h2 / h3，锚点 id 与正文标题共用同一份数据，不会对不上。≥900px 固定右栏，窄屏折叠到正文顶部，滚动时高亮跟随当前章节。
- **响应式**：卡片网格从两列降到单列，375 / 768 / 1440 三档宽度下均无横向滚动条。

## 难点与取舍

### 路由选了 hash 模式

GitHub Pages 是纯静态托管，没有服务端 rewrite。history 模式下直接访问 `/posts/xxx` 会拿到 404，得额外维护 `404.html` 重定向脚本。

hash 模式下 `#` 之后的部分不参与服务器请求，刷新任意页面都不会 404，也不需要任何配置。代价是 URL 里多一个 `#`，对这个规模的站点可以接受。

### 不引入 UI 库，也不引入 Pinia

全站状态只有「主题」一项，用一个模块级 composable 就够了，引入状态管理库是纯负担。样式同理：手写 CSS 加一层设计令牌，比引入组件库再覆盖它的默认样式更可控，产物也更小。

### TOC 与正文共用一份数据

常见的做法是渲染完 HTML 再回头用正则匹配标题、补锚点，标题一旦有行内代码或标点就会对不上。

这里直接遍历 markdown-it 的 token 流：收集 h2 / h3 的文本、生成 id、写回 attrs，再渲染。锚点与正文天然一致，不需要二次匹配。

## 站内导航

- **首页**：Hero 文案、精选作品（最多 3 个）、最新 5 篇文章。
- **作品** `/projects`：卡片网格；点进去是详情页，有封面、技术栈标签、外部链接和正文。
- **文章** `/posts`：按年份分组的时间倒序列表。
- **文章详情** `/posts/:slug`：正文加右侧目录。
- **关于** `/about`：头像、简介和联系方式。
- **404**：任何未匹配的地址，以及详情页里不存在的 slug。
